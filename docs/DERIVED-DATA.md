# Data derived from Diablo II / Project Diablo 2

This document lists the game tables in the repository that **derive from data of a commercial game or of a
third-party wiki**, with their origin, their nature, their risk and a replacement option. None of this data
is a game file: it consists of constants re-encoded into structures specific to the project.

## 0. Owner's decision (2026-10-16)

**"We accept it, with attribution."** The data derived from Diablo II / Project Diablo 2 (uniques and sets, affixes, runewords,
runes, item bases, skills, monsters, texts and names) **remains in the repository**, with full attribution
(`THIRD_PARTY_NOTICES.md`, `README.md`, `DISCLAIMER.md`). **No replacement is planned for the time being**; the plan in §4 remains a
documented option, to be reopened if the owner changes their mind or upon request from a rights holder (see "Contact, takedown requests" in the README).

Framework for this decision:

- The project is a **non-profit fan project, not affiliated** with Blizzard Entertainment or with Project Diablo 2.
- The **gameplay data is re-encoded** into the project's own structures: the Diablo II LoD 1.13c values were read from the game's
  data tables (`UniqueItems.txt`, `MonStats.txt`, `Levels.txt`...) by the generators of `tools/vanilla` and `tools/audit`, and some
  official name pairs of `src/i18n/en.json` come from the game's `string.tbl` files (see §1); the Project Diablo 2 values come from the
  Project Diablo 2 wiki and from Project Diablo 2's season-13 data tables as published in the pd2-tools repository (skill numbers,
  synergies, some monster values); third-party copies of the 1.13 tables (fabd/diablo2) were used for the early study and for
  cross-checks (see `THIRD_PARTY_NOTICES.md` §3; the Fandom Diablo wiki is credited as a consulted reference). No game file is shipped: Diablo II's graphics,
  sounds and maps come only from the player's own archives, read locally.
- Wiki excerpts remain under their licence: **CC BY-SA 4.0** for the Project Diablo 2 wiki (wiki footer:
  "Content is available under Creative Commons Attribution-ShareAlike 4.0 International"). The Fandom Diablo wiki (**CC BY-SA 3.0**,
  the default licence for text on Fandom wikis) is credited as a precaution, as a consulted reference: **no file in the repository is
  identified as coming from it** (verified: no script or dataset of the repository queries it; it appears only as a link in `docs/internal/`, and its images were only viewed as art references, never committed), but we
  cannot prove that no value was ever read from it. Should a file turn out to be derived from it, that file keeps version 3.0 (see `LICENSE-DATA.md`).
  The ShareAlike clause applies to the data taken from the wikis and to their adaptations.
- Official names (items, monsters, areas, skills) remain trademarks or game names of their owners; they are
  used to identify the content, without claiming any official connection.

**Technical status: nothing has been replaced**; only files not needed at runtime have been removed (see §3).

Nature legend: **F** = re-encoded gameplay facts (numeric values, formulas, stat tables:
generally not protectable as such); **T** = copy of text / names / structure (official names,
descriptions, labels); **W** = extraction from a CC BY-SA wiki (attribution and ShareAlike, see
`THIRD_PARTY_NOTICES.md`). Risk: high / medium / low.

## 2. Tools that read the user's files (no embedded data)

`tools/d2import/*` (MPQ/DS1/DC6/DCC readers, exporters), `tools/d2audio/*`, `tools/audit/*` and
`tools/i18n/*` read archives **owned by the user** (`D2_PRIVATE_DIR`); no output file
is tracked by git. `src/platform/d2local*.ts` does the same in the browser (OPFS), without uploading anything.

## 3. Files removed from the repository (generation only)

The game and the tests run without them. Removed (and added to `.gitignore` for the dumps):

| Removed | Why |
|---|---|
| `tools/itemdata/pd2-{uniques,runewords,bases,sets,runes}.json`, `tools/skilldata/pd2-skills.json` | raw dumps of the PD2 wiki (CC BY-SA; `pd2-skills.json`: PD2 season-13 `Skills.txt` / `SkillDesc.txt`, game data), can be regenerated with `python3 mods/pd2/tools/itemdata/extract-pd2.py` and `mods/pd2/tools/skilldata/pd2skills.py` |
| `tools/itemdata/names-fr.py`, `names-fr-uniques.py`, `names-fr-runewords.py` | "English name -> official French name" dictionaries copied from the game's localisation |
| `tools/itemdata/affixes-fr.json`, `affixes-en.json`, `en-lot2.json` | tables of official affix / item names (FR/EN) |

Honest consequence: `gen-uniques.py`, `gen-bases.py`, `gen-runewords.py`, `gen-affixes.ts` and
`tools/d2s/gen-tables.ts` **can no longer be re-run as they are** without rebuilding these dictionaries from
your own game files (`tools/i18n/official.ts` produces the official pairs from your archives).
The generated files in `src/data` are therefore now the **source of truth**; the scripts remain as
documentation of the method.

**Kept because it is needed**: `mods/pd2/tools/skilldata/pd2-wiki.json` (345 KB, raw extraction from the PD2 wiki, CC BY-SA); per-file licences: `LICENSE-DATA.md`:
`mods/pd2/tests/unit/skills-pd2.test.ts` checks that every field of `mods/pd2/data/skills.ts` reproduces the wiki tables at
levels 1 to 60. If the owner replaces `mods/pd2/data/skills.ts` with our own curves, this JSON and this test can
be removed together.

## 4. Proposed replacement plan (not carried out)

1. **Original names**: define an `id -> original name` dictionary (EN + FR) for uniques, sets, runewords,
   bases, affixes, boss monsters and areas; the internal `id`s (not displayed) can stay. The
   official names then become unnecessary in `src/data` and `src/i18n/en.json`. Effort: 2-3 days, mechanical
   (renaming script + review).
2. **Values**: keep the formulas and ranges (facts); for uniques/sets, either regenerate
   "inspired" values (±10-15 % jitter and recombination of properties), or move to an entirely original item
   catalogue (procedural generation of legendaries). Recommendation: renaming + a reduced
   catalogue; the rest of the balancing (bots) is recalibrated with `npm run bots`.
3. **PD2 wiki**: if values taken from the wiki are kept, keep the CC BY-SA 4.0 attribution and publish those
   files under the same licence; otherwise replace them with our own (parametric) curves and delete
   `pd2-wiki.json` + the associated test.
4. **Loading from the player's files** (maximal option): ship only the engine and an original
   catalogue; generate the "classic" tables at install time from the archives owned by the player
   (the import code already exists for sprites). High effort (1-2 weeks), removes all content risk.
5. **Tests**: tests that reference official names (`tests/unit/*`) follow by id; plan a
   recalibration pass for the bots and for the in-game changelog (`src/ui/changelog.ts`).
